You are evaluating whether a generated tribal knowledge book contains one gold atomic claim.

Gold evidence explains why the gold claim is true.
Do NOT count gold evidence as evidence in the book.
Only score what the book itself says.

claim_text states the claim in full and defines its meaning.
Every claim has a main finding: the fact the claim exists to establish. It is stated in the first sentence of claim_text together with the specifics that identify it. The rest of claim_text and the later must_include points add the cause, the mechanism, a precise figure, a procedure, or a proof that something is absent.
match.must_include lists the points to look for in the book. A point counts when its meaning is in the book, as defined below; exact wording is not required. Details that appear in claim_text but not in must_include, including numbers, are not required and must not lower the rating of the main finding.
Use match.must_not_include to detect contradictions. A must_not_include point is found only when the book asserts the forbidden fact as the real state of things. A description that reaches the same effect by different wording, or a mention made in order to deny it, is not a contradiction.

A must_include point is found when its meaning is present in the book, in any wording:
- A point that joins several facts is found when the book states each fact that matters to its meaning. Two expressions of the same quantity are interchangeable. A half-met point is not found when the missing half is a distinct fact the point names.
- A numeric point is found when the book gives the same quantity and the same rule behind it, even if the value is shifted or stale. If the point itself lists an alternative figure, the book's use of that figure is accepted. A point is not found when the number implies a different rule or threshold, or when the point names a specific count, span or amount and the book gives none.
- The parts of a point may sit in different places in the book. Read the book as a whole and combine them.
- A point about a formula or rule is found only when the book expresses the same relationship with all of its parts. If the point names coefficients, weights or thresholds, the book must give them (in words or any form); naming the kinds of adjustment without their values is not enough.
- A fact that follows directly from what the book states counts as stated, for example a list of observed values that leaves one out, or a label saying an item is excluded and has no rows. Do not require the claim's own framing words (silent, deliberate, dead, invisible, pending); a different label for the same thing (legacy, unnamed, historical) does not defeat a point.
- A point that asserts a separate, concrete element is found only when a passage of the book says that element. Such elements are who or what created something and by what means, what a fix actually did, that nothing refreshes, reads, writes or marks something, that something was put on hold, how many items or how long, the date on which a boundary falls, and which source holds or verifies the figure. Citing a commit, a job, a table, a creation date or a neighbouring fact is not enough, and absence or non-refresh must not be inferred from silence. If the book never touches the element, write "none" and set found to false.

Rating the main finding (step 4):
- "full" when the book states the headline and every must_include point is found, or when the only missing points merely add interpretation, intent or consequence of facts the book does state.
- "part" when the headline is stated but any must_include point that asserts a separate concrete element (as listed above) is not found. Also "part" when the book gives only a neighbouring fact or a date without the claim's substance.
- Do not mark "part" because the book words things differently from the claim, because it omits specifics that appear only in claim_text, or because it adds extra context such as a different experiment or arm, as long as it does not state the opposite of the headline and the must_include points are carried.
- When the single must_include point is the headline itself and the book carries its meaning, rate "full"; do not demand extra mechanism the point does not name.
- A book that describes the opposite of the headline, or never touches the topic, is "none".

Work in this order:
1. Read the whole book first. List every passage that touches the topic of the claim: quote each passage and name the section it comes from. The passages that matter are often spread across the book.
2. State the claim's main finding in one sentence, with its identifying specifics.
3. For each must_include point, in the order given, decide from those passages whether its meaning is present. Quote the passage or passages that carry it; if nothing in the book carries it, write "none" and set found to false. Do the same for each must_not_include point.
4. Decide whether the book states the main finding: "full" when the book states it with its identifying specifics, "part" when the book states it only in part or without the specifics that identify it, "none" when the book does not state it, even if it states other must_include points.
5. The most common error on this task is calling a point not found when the book does state it, in other words or in another place. Before you set found to false for any point, search the book once more for it.

The verdict is computed from your decisions: contradicted if any must_not_include point is found; otherwise correct when the main finding is "full", even if a must_include point that explains, refines or quantifies it is not found; partial when the main finding is "part"; missing when the main finding is "none". Fill in verdict with your own call as well.

points must have exactly one entry per must_include point, in the same order. forbidden_points must have exactly one entry per must_not_include point; use an empty list when there are none.

book_evidence is separate from the verdict and only records how the book supports what it says: specific when the book points to a concrete source for the claim (a code path, a table or query, a dashboard, an experiment, or a reference), weak when it supports the claim without a concrete source, none when it only states the fact or omits it.
